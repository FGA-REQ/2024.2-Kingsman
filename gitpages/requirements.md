# Requisitos

Os requisitos do sistema Kingsman são divididos entre requisitos funcionais e não funcionais. Os **requisitos funcionais** descrevem as funcionalidades do sistema, enquanto os **não funcionais** abordam aspectos como desempenho, segurança e usabilidade.

## Requisitos Funcionais

### 1. Criação de Roteiros de Viagem Personalizados
- O sistema deve permitir a criação de roteiros de viagem com base nas preferências do usuário, como destinos escolhidos e tipos de atividades selecionadas.
- Sugestões de atividades devem ser personalizadas com base nas preferências do usuário, considerando a proximidade e a disponibilidade.
- O sistema deve possibilitar a edição manual dos roteiros após sua criação inicial.

---

### 2. Cadastro de Destinos e Viagens
- O sistema deve permitir o cadastro de destinos.
- O sistema deve permitir a edição de informações de destinos e viagens registradas previamente.

---

### 3. Sugestões de Atividades
- O sistema deve permitir que o usuário visualize uma lista de atividades filtradas por categorias como "Gastronomia" e "Lazer".
- O usuário deve poder marcar ou desmarcar atividades de interesse usando checkboxes.
- O sistema deve permitir que o usuário visualize informações detalhadas sobre cada atividade selecionada, como descrição e localização.

---

### 4. Salvar e Gerenciar Roteiros
- O sistema deve permitir acesso ao histórico de roteiros anteriores.
- O histórico deve incluir nome, datas e atividades realizadas nos destinos.
- Deve permitir busca por nome do roteiro, destinos ou datas.

---

## Requisitos Não Funcionais

### 1. Desempenho
- O sistema deve processar e responder às solicitações do usuário em menos de 5 segundos para garantir uma experiência ágil.

---

### 2. Segurança
- Deve proteger os dados dos usuários, especialmente informações pessoais, e implementar autenticação segura no cadastro e login.

---

### 3. Usabilidade
- A interface deve ser intuitiva e fácil de usar, permitindo que os usuários naveguem e usem as funcionalidades sem necessidade de treinamento extensivo.

--- 

### 4. Disponibilidade
- O sistema deve estar disponível pelo menos 95,0% do tempo para garantir acesso constante.

---

### 5. Compatibilidade
- Deve ser compatível com os navegadores mais populares e funcionar em dispositivos móveis e desktops.

---

### 6. Escalabilidade
- O sistema deve ser escalável para suportar um número crescente de usuários sem perda significativa de desempenho.

---

## Conclusão

A atualização dos requisitos do sistema **Kingsman**, alinhada com as definições do **Definition of Ready (DoR)**, garante que as funcionalidades estejam bem detalhadas e preparadas para desenvolvimento. Com a definição clara de requisitos funcionais e não funcionais, a equipe tem agora uma visão precisa do que precisa ser implementado, assegurando um processo de desenvolvimento mais ágil e eficiente. Esta organização permitirá que as tarefas sejam executadas dentro dos prazos estabelecidos, com maior controle sobre o progresso e a qualidade do sistema.
